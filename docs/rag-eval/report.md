## 一、黄金集重生成（长度分层修正）

上一轮 recall@5 = 0.5406 的归因结论：`generate_questions` 按 `created_at DESC` 取文档，`--limit 100` 实际取到**最短的 100 篇**（期望文档正文中位数仅 150 字符），薄文档不可检索是主要瓶颈。本次按设计口径（~20 篇 × 5 问）重生成。

命令（backend 目录）：

```powershell
python -m scripts.rag_eval --generate-questions --min-chars 800 --max-docs 22 --per-doc 5 --clear
```

- 结果：**110 条问题，覆盖 22 篇文档**，耗时 **103.2 s**（约 4.7 s/篇 LLM 调用）
- 文档选取：`--clear` 先清空 `rag_eval_set`；过滤正文（chunks 内容总长）≥800 字符后按**正文长度降序**取前 22 篇
- 覆盖文档正文长度：min 5,515 / median 7,893 / max 16,574 字符（对照上一轮中位数 150）
- 全库背景：ready 文档 192 篇，其中正文 ≥800 字符 82 篇、≥1600 字符 68 篇
- SQL 核对：`SELECT count(*) FROM rag_eval_set;` → **110**；`count(DISTINCT expected_doc_ids->>0)` → **22**

脚本改动（`backend/scripts/rag_eval.py`，仅新增参数，未改检索代码）：
- `--max-docs N`：最多取 N 篇文档出题（按正文长度降序截断）
- `--min-chars N`：跳过正文总长小于 N 的文档
- `--clear`：出题前用现有 session 执行 `DELETE FROM rag_eval_set`
- 未传 `--max-docs` / `--min-chars` 时保持原分页与 `--limit` 语义不变
