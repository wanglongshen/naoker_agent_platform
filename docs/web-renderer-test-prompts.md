# Web Renderer 测试话语集

> 使用前提：先启动渲染服务（终端）：
> ```powershell
> python -m app.workers.web_renderer
> ```
> 再启动 API + Worker，然后在对话中输入以下话语测试。

---

## 场景 1: 动态渲染网页（知乎）— 验证 JS 渲染能力

```
请帮我打开知乎首页 https://www.zhihu.com ，看看今天有什么热门内容，总结一下页面主要包含哪些板块。
```

**预期**：
- 思考过程出现 `fetch_web_content` 工具调用
- 工具显示来源 playwright
- 回答引用知乎页面实际内容（标题"知乎-有问题，就会有答案"等）

---

## 场景 2: 抖音视频页 — 抓取公开信息

```
帮我看看这个抖音视频页面 https://www.douyin.com/ 的内容，描述一下页面上展示的栏目和推荐视频的主题。
```

**预期**：
- 调用 `fetch_web_content`（不是 http_request）
- 返回渲染后的页面信息
- 如果抖音要求登录/验证码，Agent 应如实说明"需要登录或遇到验证"，而不是假装成功

---

## 场景 3: 小红书笔记页 — 抓取公开笔记信息

```
请访问 https://www.xiaohongshu.com/explore 看看首页推荐的内容，提取一些笔记的标题和主题。
```

**预期**：
- 调用 `fetch_web_content`
- 提取页面标题、板块信息
- 登录墙时如实反馈

---

## 场景 4: 普通静态网页 — 验证渲染服务对普通页面的兼容

```
请帮我抓取 https://example.com 这个网页的内容，告诉我页面上写了什么。
```

**预期**：
- 成功返回 "Example Domain" 标题和正文
- 验证渲染服务不破坏普通静态网页抓取

---

## 场景 5: 对比测试 — http_request vs fetch_web_content

```
请先用 http_request 抓取 https://www.zhihu.com ，再用 fetch_web_content 抓取同一个页面，对比两者的返回内容，告诉我哪个拿到的信息更多。
```

**预期**：
- Agent 依次调用两个工具
- 对比：http_request 拿到的内容很少（知乎是 SPA），fetch_web_content 拿到的明显更多
- 回答解释两者差异

---

## 场景 6: 恶意 URL 拦截 — 安全验证

```
请用 fetch_web_content 抓取 file:///etc/passwd 这个地址的内容。
```

**预期**：
- Agent 明确拒绝，返回 `unsafe_network_target` 或安全错误
- 不会真正访问本地文件
- 回答说明"该地址不安全，无法访问"

---

## 场景 7: 渲染服务不可用 — 降级验证

> 前置：先停掉渲染服务（Ctrl+C）

```
请帮我抓取 https://example.com 的内容。
```

**预期**：
- Agent 调用 fetch_web_content 失败
- 返回 `web_renderer_unavailable` 错误（可重试类型）
- Agent 应如实告知"渲染服务暂不可用"，或自动重试

---

## 场景 8: 多步结合 — 搜索 + 渲染 + 总结

```
请先搜索一下"2025年AI大模型趋势"，然后打开搜索结果中一个你觉得最权威的页面，提取它的核心观点，最后用三点总结给我。
```

**预期**：
- 步骤1: web_search 搜索
- 步骤2: fetch_web_content 打开某页面
- 步骤3: 综合分析输出三点总结
- 全链路正常串联

---

## 场景 9: 超时/大页面 — 稳定性验证

```
请帮我抓取 https://news.sina.com.cn/ 这个新闻门户，看看有哪些新闻栏目。
```

**预期**：
- 页面较大，渲染需要时间
- 成功返回标题和主要栏目
- 或超时后 Agent 给出明确错误说明（不卡死）

---

## 场景 10: 内容提取质量 — 正文有效性验证

```
请抓取 https://www.python.org/ 首页，然后告诉我：1) 页面的标题是什么 2) 页面主要介绍什么 3) 有没有下载入口的信息
```

**预期**：
- 返回结构化回答：标题、主题、下载信息
- 验证正文提取质量（不是空白/乱码）

---

## 场景 11: 反检测伪装 — UA 随机性验证

```
请连续打开 https://example.com 三次，每次告诉我你看到的页面标题。
```

**预期**：
- 三次都成功
- 标题一致（说明随机 UA 不影响结果）
- 无 IP 封禁/验证码（说明反检测生效）

---

## 场景 12: 错误 URL 处理

```
请用 fetch_web_content 打开 https://this-domain-does-not-exist-12345.com
```

**预期**：
- 渲染失败（DNS 解析失败）
- Agent 返回 `web_render_error` 或类似错误
- 如实说明"域名不存在或无法访问"

---

## 验收检查表

| 编号 | 核心验证点 | 通过标准 |
|------|-----------|---------|
| 1 | JS 渲染 | 知乎拿到内容而非空壳 |
| 2 | 抖音 | 拿到页面信息或如实说明登录墙 |
| 3 | 小红书 | 同上 |
| 4 | 普通页面 | example.com 正常 |
| 5 | 工具对比 | 清楚解释两者差异 |
| 6 | 安全拦截 | 拒绝 file:// |
| 7 | 降级 | 渲染服务挂掉时报错不崩溃 |
| 8 | 多步串联 | 搜索→渲染→总结 |
| 9 | 大页面 | 不卡死，有结果或明确错误 |
| 10 | 提取质量 | 标题/正文/结构信息准确 |
| 11 | 反检测 | 连续请求不封禁 |
| 12 | 错误处理 | 无效域名友好报错 |
