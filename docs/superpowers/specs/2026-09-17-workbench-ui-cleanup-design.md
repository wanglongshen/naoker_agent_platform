# 工作台界面整理（6 项）设计

- 日期：2026-09-17
- 状态：设计已确认（顶栏方案选 A），待转实施计划

## 1. 背景与目标

用户对工作台提出 6 项调整，均基于真实截图与现场观察：

1. 「方案中心」页面无用，去掉。
2. 「知识库管理」侧栏位置移到「文件管理」下面。
3. 「DSH 设置」应始终显示（撤销 2026-09-17 的"仅实例运行时显示"）。
4. 删除当前所有测试对话，换成正常、合规、专业的示例对话。
5. 顶部导航栏在不同页面呈现两种样式（有的带「飞书已连接 + 平台登录」，有的只有头像），必须统一。
6. DSH 工作区没有占满内容区，右侧空出一块。

## 3. 改动设计

### 3.1 移除「方案中心」

- 删除 `frontend/src/app/(dashboard)/generations/page.tsx`，以及仅被该页面引用的组件文件（实施时用引用检索逐个确认，被其它页面复用的组件保留）。
- 移除侧栏菜单项（`app-sidebar.tsx:132`）与 `copy.navigation.generations` 的引用。
- **保留后端**：任务链 API、worker、数据表、DSH 子任务执行器全部不动（无前台入口，随时可恢复）。
- 验收：侧栏无「方案中心」；`/generations` 返回 404（页面已删除）。

### 3.2 侧栏顺序

目标顺序：`我的文件 → 账户 → 对话审计 → 文件管理 → 知识库管理 → 用户管理 → 角色管理 → DSH 设置 → 退出登录`。

实现：调整 `app-sidebar.tsx` 菜单项数组顺序，不改其它属性（图标、权限过滤、`onNavigate` 行为不变）。

### 3.3 DSH 设置常显

- 移除 `isDshRoute && instanceState === "running"` 条件，任何页面、任何实例状态都渲染。
- 点击行为（统一为一条路径）：`router.push("/agent?settings=1")`；`DshWorkspace` 解析 `settings=1`（与 `new=1` 同款：`ready` 后发送 `open-settings` 桥命令，随后清掉 URL 参数）。若实例未运行，工作区已有的自动拉起逻辑先启动实例，就绪后再发命令。

### 3.4 会话清理与专业示例对话

**清理范围**（仅当前登录用户 `admin` 的 DSH home）：

1. DSH 会话存储中的全部会话（含任务链内部会话与测试聊天）。
2. 平台 `dsh_sessions` 同步表中该用户的记录。
3. 浏览器 `localStorage` 的 `dsh:last-session:<uid>` 记忆。

**删除机制（实施第一步先确认，不猜）**：候选优先级 —— ① DSH 自带的会话删除接口/命令；② DSH 会话存储文件 + 索引的删除；③ 直接操作其持久化文件。实施时先读 DSH 源码与会话存储目录确认哪条可行，再写清理脚本（幂等，可重复执行）。

**示例对话播种**：用 DSH headless 真跑 5 条，产出真实答案（标题取自问题首句）：

| # | 问题（标题来源） | 覆盖能力 |
| --- | --- | --- |
| 1 | 为新品制定一份抖音千川投放策略，包含出价与预算分配 | 千川投放库 + 方案结构 |
| 2 | 短视频内容选题与脚本框架怎么设计？ | 短视频与内容库 |
| 3 | 直播间转化率提升的关键动作有哪些？ | 直播运营库 |
| 4 | 广告投放中哪些表述属于平台规则与广告法风险？ | 平台规则库 |
| 5 | 拆解一个生鲜类目的经营案例，提炼可复用打法 | 行业案例库 |

- 成本：5 次真实 LLM 调用，约 3-6 分钟，有 token 消耗。
- 播种后校验：会话出现在侧栏、标题正确、`dsh_sessions` 同步表有对应记录。

### 3.5 顶栏统一（方案 A）

**目标**：全站只有一套顶栏 —— 左侧「脑」标记 + 产品名，右侧用户区（头像 + 姓名下拉）；「飞书连接状态」「平台登录」收进用户下拉菜单，功能不丢。

实现：

- 以 `AppHeader` 为唯一顶栏组件，补齐左侧品牌区（logo + 产品名）与下拉菜单项：
  - `飞书：已连接 / 连接飞书`（沿用 `FeishuConnect` 的连接逻辑与弹窗，触发点由独立按钮改为菜单项）
  - `平台登录`（沿用 `PlatformLoginModal`）
  - `个人资料`、`退出登录`（保持现状）
- `(agent)` 路由组改用同一顶栏：删除 `ConversationTopBar` 的使用与文件。
- 两个 shell（`AppShell` / `DashboardShell`）保持各自布局与折叠行为不变——本次只统一顶栏，不动侧栏壳。
- 视觉：沿用现有暖色渐变顶栏样式（`.conversation-top-bar` 的视觉规范迁移到统一组件），保证与侧栏橙色一致。

### 3.6 DSH 工作区占满内容区

- **第一步：定位根因**。通过现有 postMessage 桥加一个临时 `probe-layout` 命令，回传 DSH 应用框架的 `grid-template-columns`、会话列与内容列的 `getBoundingClientRect()`；在平台侧打印结果，确认是「右侧轨道残留」还是「会话列宽度限制」。
- **第二步：修复**。按测量结果在 `sidebar-hide.ts`（或同目录新增一个布局修正模块）注入最小 CSS：
  - 若为轨道残留 → 将 AppFrame 的所有轨道中除内容轨外全部归零；
  - 若为会话列宽度限制 → 对其容器注入 `max-width: none; width: 100%`。
- **第三步**：移除临时探针（除非它被证明对后续排查有长期价值，则保留为调试命令并写进 NOTES）。
- 约束：只改注入的 CSS/插件逻辑，不改 DSH 本体。

## 5. 风险与边界

- **不删除后端任务链**：只摘除前台入口；若后续要恢复，重新加菜单项即可。
- **DSH 会话删除**：先确认官方删除路径再动手；清理范围严格限定为当前用户 home，绝不触碰其它用户目录。
- **示例对话消耗真实 token**：执行前告知用户；若用户希望换成 3 条或其它主题，播种前可调整。
- **布局修正 CSS 依赖 DSH 内部类名**：与现有侧栏隐藏同样有"DSH 升级可能失效"的风险，已记录在 DSH 升级 SOP 的回归清单中。
- **顶栏统一后 `ConversationTopBar` 删除**：其单测一并移除/迁移，避免留下无引用文件。
