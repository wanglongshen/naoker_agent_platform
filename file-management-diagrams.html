📁 文件管理系统 — 设计图全集

技术栈：Next.js 16 + React 19 + Ant Design 6 (前端)  |  FastAPI + PostgreSQL (后端)
方案 B：新建独立文件模块  |  两层入口：管理员全局视图 + 个人文件管理

核心设计原则： 文件管理模块与 Agent 附件系统分离。新建 file_folders + file_objects 表，新建 /api/files 路由。 Agent 对话中的附件通过"引用链接"关联到文件库，不受附件 90 天清理策略影响。文件永久保留，用户可独立上传。

2. 数据库 ER 图

file_folders 使用物化路径（materialized path）实现无限嵌套；file_objects 记录每个文件的元数据。与已有 agent_attachments 表通过 source_attachment_id 建立弱引用。

erDiagram users ||--o{ file_folders : "owner_user_id" users ||--o{ file_objects : "owner_user_id" file_folders ||--o{ file_folders : "parent_folder_id" file_folders ||--o{ file_objects : "folder_id" agent_attachments ||--o| file_objects : "source_attachment_id" users { uuid id PK "用户 ID" } file_folders { uuid id PK "文件夹 ID" uuid owner_user_id FK "所属用户" uuid parent_folder_id FK "父文件夹 (可空=根目录)" varchar name "文件夹名称" text path "物化路径 例: /root/docs/" int depth "深度" bigint child_file_count "子文件数" bigint total_size_bytes "累计大小" uuid created_by "创建人" timestamptz created_at timestamptz updated_at boolean is_deleted "软删除" } file_objects { uuid id PK "文件 ID" uuid owner_user_id FK "所属用户" uuid folder_id FK "所在文件夹 (可空)" varchar storage_key "存储路径键" varchar filename "显示名称" varchar original_filename "原始文件名" varchar media_type "MIME 类型" bigint size_bytes "文件大小" varchar sha256 "SHA-256 哈希" text extracted_text "提取文本 (3MB 以内)" varchar preview_status "预览状态: none/ready/processing/failed" varchar preview_path "预览缓存路径" uuid source_attachment_id FK "关联附件 (可空)" uuid created_by "上传人" timestamptz created_at timestamptz updated_at timestamptz expires_at "过期时间 (可空=永久)" boolean is_deleted "软删除" } agent_attachments { uuid id PK "附件 ID" uuid owner_user_id FK "所属用户" uuid session_id FK "所属会话" varchar storage_key "存储路径" varchar filename "文件名" varchar original_filename "原始文件名" varchar media_type "MIME 类型" bigint size_bytes "大小" varchar sha256 "哈希" varchar extraction_status "提取状态" text extracted_text "提取文本" timestamptz expires_at "过期时间 (90天)" }
