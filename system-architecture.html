1事件通道（两条，实测）

Worker 进程内所有事件经 EventBus 微秒级直发；Redis Streams 提供跨进程低延迟路径。SSE Generator 统一从 EventBus 读取。

通道 ② EventBus（同进程）主通道 · 微秒级

Worker 与 SSE 同进程时，event_bus.publish(EventItem) 将完整 payload 放入 asyncio.Queue，SSE 直读直发。零网络、零数据库查询。所有事件均经过，包括成功终态。

通道 ① Redis Streams（XADD / XREADGROUP）跨进程 · 批量

非 Pub/Sub。_batch_flush_loop 每 32ms 或累积 20 条 pipeline XADD 至固定 stream agent:events（maxlen 10000）；_subscribe_loop XREADGROUP 消费后注入 EventBus。

覆盖 _persist_and_notify（普通事件）与 _persist_terminal_and_notify（失败/取消终态）。成功终态由 _persist_successful_completion 直发 EventBus，不经 Redis，由 30s 补偿查询兜底。

PostgreSQL NOTIFY（任务唤醒）独立用途

创建 run 时 pg_notify("new_run", run_id)，Worker 端 asyncpg LISTEN 置位唤醒事件立即抢任务。仅负责调度，不参与事件流。

成功终态（原子提交）

_persist_successful_completion 在同一事务内写：answer_completed · step_completed · attempt→succeeded · run→succeeded · run.result（final_answer + source_event_sequence）。三个 EventItem 发布后直发 EventBus，不经 Redis 批缓冲。

4SSE Generator 行为

GET /api/agent/runs/{id}/stream — Cookie 鉴权 + CSRF origin 校验。

  1. 重放：按 last-event-id / after_seq 调用 _events_after 逐条发送（每条间隔 30ms）；
  2. 直发：EventBus 队列取出，仅当 seq > lastSeenSeq 发送（天然去重，无 gap 检测）；
  3. 终态判定：每轮循环查询 AgentRun.status ∈ {succeeded, failed, cancelled, completed}，命中则补齐剩余事件后 break 关闭；
  4. 心跳：队列阻塞 30s 超时 → 发送 :keepalive + 补偿查询 _events_after（单次 ≤200 条）。

断线兜底（Reconciliation）

onerror 且 run 非终态 → performReconciliation：REST getRun 拉取最新状态合并（已有流式文本时跳过覆盖）；终态则关闭连接并通知。会话页另有 reconcileSession + 警告 Alert。

5Worker 生命周期

FastAPI 进程内常驻后台任务（单进程开发环境 = 同进程 EventBus 直通）。

run()→ LISTEN "new_run"→ _claim_and_execute→ _do_process_attempt→ _persist_successful_completion
  • 两步规划：LLM 流式收集全文 → _parse_json_content 解析，失败则 JSON mode create_plan 重试 → Pydantic 校验 → plan_created；
  • 租约：每 lease/3 秒续期（lease=60s），_recover_expired 回收过期任务；
  • 异常分类：classify_agent_failure（deepseek_auth_error / deepseek_config_error / deepseek_timeout / worker_unhandled_error），可重试类最多 3 次；
  • 超时：run_timeout_seconds=120 → run_failed；步骤数耗尽 → run_failed（max_steps_exceeded）。

6前端渲染链路

SSE → 内存累积 → 每帧一次 React 更新 → 增量 Markdown。

SSE 事件→ reduceRunStream(stateRef)→ RAF 帧合并 ≈60次/s→ setState(完整快照)→ ProgressiveMarkdown
  • CompletedBlock：已完成块（空行 / 代码围栏 / 表格边界切分）React.memo + stable key，永不重解析；
  • StreamingTail：活跃尾部 RAF 打字动画（20ms/字符）；终态且 wasLiveStreamed 时先打字播放、结束后切换为完整渲染；
  • liveStreamed：由 eventSource.onopen 置位，用于区分历史答案（直接渲染）与实时流式答案（打字动画）；
  • ThoughtNarrative：思维区以 narrativeEvents 驱动，useTypingText 打字呈现；
  • PERF 日志：answer_completed / run_succeeded 时输出性能摘要（事件数 / 帧数 / 重连数 / 答案长度）。
