简单 RBAC 系统设计图

技术栈：Next.js + FastAPI + PostgreSQL。首期实现登录与用户管理，角色管理页预留。

1. 总体认证与鉴权流程

flowchart TD A[用户访问 Next.js 管理端] --> B{存在登录态 Cookie?} B -- 否 --> C[登录页] C --> D[POST /api/auth/login] D --> E{账号、密码与状态校验} E -- 失败 --> F[返回统一登录失败提示] F --> C E -- 成功 --> G[签发 JWT 并写入 HttpOnly Cookie] G --> H[跳转用户管理页] B -- 是 --> I[GET /api/auth/me] H --> I I --> J{JWT 有效且用户已启用?} J -- 否 --> K[清除 Cookie 并跳转登录页] J -- 是 --> L[查询用户角色和权限] L --> M[前端按权限渲染菜单和按钮] M --> N[调用受保护接口] N --> O[后端验证 JWT、状态与权限] O --> P{具备接口权限?} P -- 否 --> Q[403 无权限] P -- 是 --> R[执行业务并返回结果]

3. 用户管理操作流程

flowchart TD A[进入用户管理页] --> B[校验 user:read] B --> C[GET /api/users 查询列表] C --> D{管理员操作} D --> E[新增用户] E --> E1[校验 user:create] E1 --> E2[填写资料、初始密码、状态和角色] E2 --> E3[POST /api/users] E3 --> E4[校验账号唯一性、密码规则和角色有效性] E4 --> E5[创建用户并绑定角色] D --> F[编辑用户] F --> F1[校验 user:update] F1 --> F2[PUT /api/users/:id] F2 --> F3[更新资料；改角色额外校验 user:assign_role] D --> G[启用或停用] G --> G1[校验 user:status] G1 --> G2[PATCH /api/users/:id/status] G2 --> G3[不可停用自己或最后一个有效超级管理员] D --> H[重置密码] H --> H1[校验 user:reset_password] H1 --> H2[POST /api/users/:id/reset-password] H2 --> H3[Argon2 哈希后保存] D --> I[删除用户] I --> I1[校验 user:delete 并二次确认] I1 --> I2[DELETE /api/users/:id] I2 --> I3[不可删除自己或最后一个有效超级管理员] E5 --> C F3 --> C G3 --> C H3 --> C I3 --> C

flowchart LR Next[Next.js 前端] --> Login[POST /api/auth/login] Next --> Logout[POST /api/auth/logout] Next --> Me[GET /api/auth/me] Next --> List[GET /api/users] Next --> Create[POST /api/users] Next --> Update[PUT /api/users/:id] Next --> Delete[DELETE /api/users/:id] Next --> Status[PATCH /api/users/:id/status] Next --> Reset[POST /api/users/:id/reset-password] Login --> Service[FastAPI 服务层] Logout --> Service Me --> Guard[JWT 与权限依赖] List --> Guard Create --> Guard Update --> Guard Delete --> Guard Status --> Guard Reset --> Guard Guard --> Service Service --> DB[(PostgreSQL)] DB --- Users[(users)] DB --- Roles[(roles)] DB --- Permissions[(permissions)] DB --- UR[(user_roles)] DB --- RP[(role_permissions)]
